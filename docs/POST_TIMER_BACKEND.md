# مؤقت المنشور — متطلبات الباكند (Node / API)

هذا الملف يصف ما يجب تنفيذه في السيرفر ليتوافق مع تطبيق Flutter (Archiarena) ويعمل **مؤقت الصفقة** على البطاقات والتفاصيل.

---

## 1) استقبال عند إنشاء المنشور

التطبيق يرسل طلب **multipart/form-data** ويضمّن (حسب نوع الحساب):

| الحقل        | النوع   | ملاحظة                          |
|-------------|---------|----------------------------------|
| `timer_days`  | رقم     | اختياري، ≥ 0                    |
| `timer_hours` | رقم     | اختياري، ≥ 0                    |

**المسارات ذات الصلة (حسب إعداد المشروع):**

- منشور المستخدم العادي: عادة `POST /home/posts` (أو ما يعادله في الـ API).
- منشور الشركة: عادة `POST /home/company/posts` (أو ما يعادله).

**المطلوب من الباكند:**

1. قراءة `timer_days` و `timer_hours` من الـ body.
2. التحقق من أنها أرقام صالحة (أو تجاهلها إن كانت فارغة/غير صالحة).
3. حفظها في قاعدة البيانات مع سجل المنشور.

**اختياري:** دعم `timer_minutes` إن أردت لاحقاً؛ التطبيق حالياً لا يرسل دقائق من شاشة «بماذا تفكر»، لكن نموذج العميل يدعم استقبالها في الاستجابة.

---

## 2) حساب وتخزين وقت انتهاء المؤقت

بعد تحديد **وقت إنشاء المنشور** (`created_at`):

```text
timer_ends_at = created_at + timer_days أيام + timer_hours ساعات + timer_minutes دقائق
```

**يُفضّل** تخزين **`timer_ends_at`** في قاعدة البيانات (نوع `timestamp` / `datetime` UTC) لأن:

- العرض في التطبيق يعتمد على **عدّ تنازلي** حتى هذا التاريخ.
- يتجنب اختلافات إعادة الحساب بين السيرفر والعميل.

---

## 3) إرجاع المنشور في JSON (قائمة + تفاصيل + بروفايل)

في **كل** استجابة فيها كائن منشور واحد، أرسل **واحداً على الأقل** مما يلي.

### الخيار A (الأفضل — يُنصح به)

حقل تاريخ انتهاء صريح بصيغة **ISO 8601** مع منطقة زمنية:

```json
{
  "id": 1,
  "title": "...",
  "timer_ends_at": "2026-04-20T15:30:00.000Z"
}
```

أسماء بديلة يتعرّف عليها التطبيق أيضاً (أي واحد كافٍ):  
`deal_ends_at`، `project_timer_ends_at`، `timer_end_at`، `deal_end_at`.

### الخيار B (بديل إن لم تُخزّن `timer_ends_at` بعد)

إرجاع وقت الإنشاء مع مدة المؤقت:

```json
{
  "created_at": "2026-04-15T10:00:00.000Z",
  "timer_days": 2,
  "timer_hours": 5,
  "timer_minutes": 0
}
```

التطبيق يحسب منها نهاية المؤقت محلياً.

### الخيار C (نص فقط — بدون عدّ تنازلي دقيق)

```json
{
  "project_timer": "يومان و 5 ساعات"
}
```

يُستخدم عندما لا يتوفر `timer_ends_at` ولا مجموعة `created_at` + `timer_*` كافية.

---

## 4) المسارات التي يجب أن تتضمن نفس الحقول

تأكد أن نفس حقول المؤقت تُرجع في:

- قائمة المنشورات الرئيسية.
- تفاصيل منشور واحد (حسب `id`).
- منشورات البروفايل / مستخدم آخر.

حتى لا يظهر المؤقت في شاشة ويختفي في أخرى.

---

## 5) ملخص تنفيذ سريع

| خطوة              | إجراء                                                                 |
|-------------------|-----------------------------------------------------------------------|
| قاعدة البيانات    | أعمدة: `timer_days`, `timer_hours` (واختياري `timer_minutes`) + `timer_ends_at` UTC. |
| POST إنشاء        | اقرأ `timer_days`, `timer_hours` → احفظ → احسب واحفظ `timer_ends_at`. |
| GET (أي منشور)    | أرجع `timer_ends_at` **أو** `created_at` + `timer_days`/`timer_hours`/`timer_minutes`. |

## مرجع التطبيق (Flutter)

- إرسال الإنشاء: `HomeApiService.createPost` و `createCompanyPost` — الحقول `timer_days`, `timer_hours`.
- التحليل: `lib/features/home/models/post_model.dart` — الدالة `_parseTimerEndsAt`.

بعد تنفيذ الباكند حسب هذا الملف، يعمل عرض المؤقت والعد التنازلي في الواجهة دون تعديل إضافي على العميل.
