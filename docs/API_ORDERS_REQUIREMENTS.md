# متطلبات API لصفحة الطلبات والأعمال

## نظرة عامة

صفحة الطلبات تظهر **للشركات فقط** وتعرض المشاريع التي نشرتها هذه الشركة. عند الدخول إلى مشروع، تظهر الصور/العروض التي رفعها الأشخاص أو الشركات من صفحة الأعمال.

---

## 1. صفحة الأعمال (My Works)

| المسار | Method | الوصف |
|--------|--------|--------|
| `/home/works` | GET | جلب قائمة منشورات "أعمالي" للمستخدم المسجل. نفس هيكل منشورات `GET /home/posts`. Query: `?page=1&limit=20` |
| `/home/works` | POST | إضافة منشور إلى الأعمال. Body (JSON): `{ "post_id": 12 }`. إذا مكرر يُرجع 200 بدون خطأ |
| `/home/works/:postId` | DELETE | حذف منشور من قائمة أعمال المستخدم |

**جدول قاعدة البيانات:** `user_works` (user_id, post_id, created_at) — مفتاح مركب (user_id, post_id).

---

## 2. صفحة الطلبات والمشاريع (للشركات)

### GET /home/orders — قائمة الطلبات

- **التعديل:** يُرجع **فقط** الطلبات التي أنشأتها **الشركة المسجلة** (تصفية حسب `user_id` من التوكن).
- **التوكن:** مطلوب (`Authorization: Bearer <token>`).
- **الصلاحية:** إذا كان المستخدم ليس شركة (`role !== 'company'`) يُرجع **403** — "صفحة الطلبات متاحة للشركات فقط."
- **الاستجابة:** `{ "data": [...], "pagination": { "page", "limit", "total" } }` — كل عنصر يحتوي `id`, `title`, `image_url`, `created_at`, وغيرها.

### POST /home/orders/:orderId/proposals — تقديم عرض

- **orderId** = معرف الطلب في جدول الطلبات. التطبيق يرسل `order_id` إن وُجد في المنشور، وإلا `post_id`.
- **مهم:** المنشورات في صفحة الأعمال يجب أن تحتوي حقل `order_id` عندما تكون مشاريع شركات (طلبات). وإلا سيظهر "الطلب غير موجود".
- **الحقول:** `message` (اختياري)، `image` (ملف — مطلوب إذا لم تُرسل رسالة). مقدّم العرض يُحدد من التوكن.
- **الاستجابة:** تتضمن `image_url`, `imageUrl`, `name`, `created_at`, `status`, `proposal_id` / `id`.

### GET /home/orders/:orderId/proposals — عروض الطلب

- قائمة العروض مع: `image_url`, `imageUrl`, `name` (مقدّم العرض), `created_at`, `status` (accepted / rejected / pending), `proposal_id`, `id`.
- **الصلاحية:** فقط صاحب الطلب (الشركة) يمكنه عرض العروض. غير المصرح يُرجع **403**.

### POST /home/orders/:orderId/proposals/:proposalId/accept — قبول عرض

- قبول عرض ورفض الباقي.

---

## 3. رفع المنشورات (ملف واحد / أي حقل)

- **POST /home/posts** و **POST /home/company/posts** يستخدمان `upload.any()` — قبول الملفات بأي اسم حقل (`images`, `image`, `files`, `file`) لتجنب خطأ Multer "Unexpected field" من التطبيق.
- **POST /home/company/posts:** عند نجاح الإنشاء، يجب إنشاء مجلد تلقائياً لضم صور العروض (انظر القسم 4).
- **مهم — عرض في الصفحة الرئيسية:** عند إنشاء مشروع شركة عبر POST /home/company/posts، يجب أن يظهر المنشور أيضاً في الصفحة الرئيسية (GET /home/posts) حتى يراه المستخدمون ويضيفوه إلى الأعمال. يُفضّل إرجاع `order_id` في المنشور لربط العروض بالطلب.

---

## 4. مجلدات الطلبات — إنشاء تلقائي

**مطلوب:** عند إنشاء المنشور/المشروع، يُنشأ المجلد **تلقائياً** في نفس العملية لضم جميع العروض لاحقاً.

### المنطق الإلزامي في الباكند

| الحدث | الإجراء الإلزامي |
|-------|------------------|
| **إنشاء منشور** (POST /home/company/posts) | عند حفظ الطلب بنجاح، إنشاء المجلد **فوراً** وبشكل تلقائي — لا خطوة إضافية |
| **تقديم عرض** (POST /home/orders/:orderId/proposals) | حفظ الصورة داخل مجلد الطلب المقابل |

### تسلسل الإنشاء التلقائي

```
1. الشركة تنشئ منشوراً → POST /home/company/posts
2. الباكند يحفظ الطلب في قاعدة البيانات
3. الباكند ينشئ المجلد تلقائياً: uploads/orders/{order_id}/
4. أي عرض لاحق يُحفظ داخل هذا المجلد
```

### هيكل المجلدات المقترح

**الخيار 1 (بسيط):** استخدام `order_id` فقط
```
uploads/orders/{order_id}/proposal_1.jpg
```

**الخيار 2:** استخدام عنوان المشروع (يُفضّل تنظيفه)
```
uploads/orders/{order_id}_{عنوان_منظف}/proposal_1.jpg
```
مثال: `uploads/orders/5_فيلا_سكنية/` أو `uploads/orders/5_villa_residential/`

**تنظيف العنوان:** استبدال المسافات بـ `_`، إزالة الأحرف الخاصة، تقصير إذا طال.

### متطلبات POST /home/company/posts (للشركات)

عند استدعاء هذا المسار، يجب أن يقوم الباكند بـ:

1. **إنشاء الطلب** في جدول الطلبات.
2. **إنشاء المجلد** `uploads/orders/{order_id}/`.
3. **إضافة المنشور إلى الصفحة الرئيسية** — يجب أن يظهر في GET /home/posts حتى يراه المستخدمون ويضيفوه إلى الأعمال. (مثلاً: إدراج في جدول المنشورات أو ربط الطلب بجدول المنشورات.)
4. **إرجاع `order_id`** في استجابة المنشور عند جلب GET /home/posts و GET /home/works — لربط العروض بالطلب عند تقديم عرض.

### لا يوجد API جديد

لا حاجة لـ API منفصل. التعديل يكون داخل:

1. **POST /home/company/posts** — بعد إدراج الطلب في قاعدة البيانات، إنشاء المجلد:
   ```js
   // مثال Node.js
   const folderPath = path.join('uploads', 'orders', orderId.toString());
   fs.mkdirSync(folderPath, { recursive: true });
   ```

2. **POST /home/orders/:orderId/proposals** — عند استلام الصورة، حفظها في مجلد الطلب:
   ```js
   // مثال: حفظ الملف في uploads/orders/{orderId}/proposal_{timestamp}.jpg
   const uploadPath = path.join('uploads', 'orders', orderId.toString(), filename);
   ```

## ملخص المسارات المضافة أو المعدّلة

| المسار | Method | ملاحظة |
|--------|--------|--------|
| `/home/works` | GET | جديد — أعمال المستخدم |
| `/home/works` | POST | جديد — إضافة منشور لأعمالي |
| `/home/works/:postId` | DELETE | جديد — حذف من أعمالي |
| `/home/orders` | GET | معدّل — طلبات الشركة المسجلة فقط، توكن مطلوب، 403 لغير الشركات |
| `/home/orders/:orderId/proposals` | GET | معدّل — إرجاع `imageUrl` مع `image_url`، 403 لغير صاحب الطلب |
| `/home/orders/:orderId/proposals` | POST | إرجاع `imageUrl` في الاستجابة |

## حل خطأ "الطلب غير موجود"

عند تقديم عرض من صفحة الأعمال، التطبيق يرسل `orderId` في المسار. يجب أن يكون هذا المعرف موجوداً في جدول الطلبات.

**الخيار 1 (مفضل):** إرجاع `order_id` في استجابة المنشورات عندما يكون المنشور مشروع شركة:
```json
{
  "id": 12,
  "order_id": 5,
  "title": "فيلا سكنية",
  ...
}
```

**الخيار 2:** في الباكند، عند استلام `POST /home/orders/:orderId/proposals`، إذا لم يُوجد طلب بالـ id، البحث عن طلب مرتبط بالمنشور (post_id = orderId) أو قبول post_id كمرجع للطلب.
